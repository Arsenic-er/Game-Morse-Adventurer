# v0.37 第 5–7 章延续设计

> 状态：2026-08-25 已批准实施。先关闭 v0.36 审计出的十项问题，再执行第 11–15 步。

## 1. 目标

v0.37 先把“空中灯火”从可玩的活动状态机补成可保存、可回顾、可叙事的完整章节，再以同一套人物身份、事件档案和原子结算能力制作第 6 章“山丘临时台”，最后建立第 7 章 QSL 与人物选择记忆的跨章基础。

## 2. 不变约束

- Windows 本地便携 EXE，离线游玩不依赖 GPU 或网络。
- 界面继续支持 `en / zh-CN / zh-TW / ja / es / de / ru` 七种语言。
- 游戏中全部呼号、人物、活动、天气和地点叙述均为虚构。
- QSO 中不显示 NPC 肖像；人物通过电报码、日志、QSL、简报和结算演出呈现。
- 玩家自由输入不写入人物档案、留言、QSL 正文或训练数据。
- 关键字段由确定性解析器验证；cwformer 只辅助语义理解，`safeToCommit:false` 必须阻止状态推进。
- 旧存档迁移不得追发金钱、技术点、活动章或成就奖励。
- 主线第 6 章不得被可选科技或金钱 grind 阻塞，剧情提供借用便携套件。

## 3. 十项审计修复

### 3.1 时间、音频与退出安全

- 活动结果保存 `completedAt`。结算以 `observedAt` 更新可信时钟和回拨守卫，以 `completedAt` 计算活动所属台站日期、年度窗口、5 月 5 日章和练习日。
- 八分钟活动时间采用单调时钟差值累计，不按定时器回调次数累计。设置菜单、窗口失焦和页面隐藏时暂停；恢复时重置采样基线，不补扣暂停时长。
- 打开设置、失焦或隐藏窗口时停止活动来台、发报音频与接收底噪；恢复后从冻结阶段重新播放一次，不重掷 NPC 或交换事实。
- 应用关闭保护从 QSO 专用状态扩展为通用 on-air activity guard。进行中的灯火局和完成未结算的灯火结果都必须拦截窗口关闭。

### 3.2 可验证的打包流程

- Electron `--qa-capture` 必须真实进入灯火故事场，验证追台、主控、Esc 暂停恢复、失败重试、结算、重载和重复结算幂等。
- QA 以具名断言和灯火截图为门槛，不以总截图数替代玩法覆盖。
- 公开克隆在依赖已缓存且网络断开时仍能构建；受校验的 INT8 模型和运行合同作为版本化运行资产随游戏仓库保存。同步脚本优先使用本地已校验资产，仅在显式更新时访问 cwformer。

### 3.3 发布与包体

- Windows 窗口和 portable EXE 使用同一像素风项目图标；原型仍未签名，README 和 Release 说明必须明确这一点。
- `v*` 标签构建除 Actions artifact 外，还应生成持久 GitHub Release 附件和 SHA-256 文件；实际发布仍需要仓库写权限。
- 浮动 Actions 主版本替换为经过审计的提交 SHA。
- JS 路由按屏幕惰性加载，最大自有 JS chunk 预算为 500 KiB；三套 CJK 像素字体改为 WOFF2，地点与场景 PNG 只做无损或像素安全优化。构建输出总量和最大资产写入 CI summary。
- 仓库保持 source-available 专有许可，不擅自改为开源许可；文档中的“开源”改为“公开源码供审阅”。cwformer 模型的作者、版本、哈希和使用许可写入第三方/随附声明。

## 4. 稳定人物与台站身份

- `personId` 表示人，`stationId` 表示电台或活动台，`callsign` 是可变别名。
- 固定人物使用稳定 ID：SORA 为 `person:sora`；固定台站为 `station:sim6jp`；灯火活动台为 `station:lights-sim5lt`。
- SORA 操作 `SIM5LT` 和 `SIM6JP` 时都累计到 `person:sora` 的唯一关系记录，同时每次日志保留当时的 on-air callsign 与 stationId。
- 程序化人物使用 `person:procedural:<npcId>`。未知旧呼号迁移为 `person:legacy:<CALLSIGN>`，不得仅凭同名自动合并。
- 人物关系状态升级为 v2，以 `personId` 去重；迁移已知固定呼号，保留未知人物的计数、时间和最后呼号。

## 5. 灯火活动档案

- 结算保存有界 `eventRunArchive`，保留故事最佳、最近二十个年度最佳和最近三十一天练习最佳。
- 单次档案包含：`eventRunId`、模式、开始/完成时刻、台站日期、分数、等级、印章、玩家呼号，以及最多七个联系人快照。
- 联系人快照包含 `personId`、`stationId`、on-air callsign、地区码、locationId、IANA timeZone、完成时刻、虚构天气代码和本地化留言 key；不保存自由文本。
- 天气由 `eventRunId + personId + completedAt` 确定性生成。当地时间由联系人完成时刻与快照 timeZone 复原。
- 历史档案是灯火地图与年度纪录的事实源；有界 QSO 日志不是二十年陈列的唯一来源。

## 6. 第 5 章完整呈现

- 剧情节拍：NOVA 留下活动信息 → 玩家追呼 SORA → SORA 邀请接管 → pile-up 主控 → 成功时 MORSE 短电文，失败时 SORA 根据原因复盘。
- 灯火地图只点亮本次实际完成联系人所在地区；选择灯火显示联系人、当地时间、虚构天气与日志留言。
- 活动页提供故事最佳、本年最佳、普通/5 月 5 日金边章和最近年度纪录，并明确台站时区、当前开放状态与下一次开放窗口。
- 增加基础、银、金、年度参与和 5 月 5 日金边章成就。迁移可识别已达到状态，但不追发奖励。
- 年度规则从 UI/日历常量抽到活动目录，灯火冻结为台站当地 5 月 1–7 日，5 月 5 日特别章。

## 7. 第 6 章“山丘临时台”

- 新增独立 `expeditionRun`，不覆盖永久 `locationId`、装备栏或仓库。
- 剧情提供一套借用配置：便携电台、线天线、电池；玩家可选择三个虚构山丘场地之一。
- 运行状态保存 fieldSite、临时 loadout、剩余供电、架台阶段、传播快照、联系人和结算状态。
- 最小流程：选择场地 → 架设天线与供电 → 发 CQ → 完成包含 QTH/PWR/ANT 的远征交换 → 收台结算。
- 错误配置降低可用时间或传播，不永久损坏玩家设备。失败、退出和重试不能复制借用装备、金钱、技术点或任务进度。
- 通关奖励解锁远征任务树入口，而不是直接授予所有远征装备。

## 8. 第 7 章跨章基础

- 增加 QSL 与人物关系页的版本化数据合同：`personId`、关联 QSO/eventRun、双方叙述 key、玩家选择枚举、创建/确认时间。
- 第 7 章使用固定选择枚举表达“相信哪段叙述、请求复核或暂不判断”，不保存玩家自由输入。
- 同一 QSL 只能确认和结算一次；选择跨重载保留，并预留给第 14 章读取。
- 坐标、人数、物资、消息编号、优先级等第 8–12 章关键字段只冻结 envelope 和验证边界，本版本不实现救援玩法。
